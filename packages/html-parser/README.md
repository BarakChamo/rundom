# Rust HTML parser boundary

This package builds a project-owned Node-API addon using html5ever over `run-dom-core` topology. One native call returns fixed-width integer records and a deduplicated immutable string pool. Zod parses the storage shape; the versioned decoder checks counts, Unicode spans and section bounds, and a shared semantic validator checks ownership indices, unique parents and acyclicity before the DOM materializes private tree records. Browser wrappers, resource execution, events and lifecycle algorithms remain in TypeScript. This is a parsing kernel, not a persistent Rust DOM backend.

`parseHTML({ markup, scriptingEnabled })` returns a typed `Result<HTMLSnapshot, NativeParseError>`. It reports invalid requests, unavailable platform addons and invalid snapshots without silently selecting another parser. Unpaired UTF-16 input is rejected before UTF-8 conversion. `getParserStatistics()` returns an independent copy of actual native invocation and capability-fallback counters. `recordParserFallback()` validates its reason and returns a Result. `InvariantError` identifies producer bugs and is never translated into capability fallback. Types derive from the exported request, snapshot and configuration schemas. `neverthrow` supplies Result, ResultAsync, ok and err; the invariant primitive lives in `src/invariant.ts`.

The public facade retains TypeScript parsing by default. Set `RUN_DOM_HTML_PARSER=rust` before loading it to select Rust for eligible inactive full-document parses. Form association, source locations, custom adapters and unpaired UTF-16 use explicitly counted complete-parser fallbacks. Active/incremental parsing, XML, fragment parsing and the empty-document shortcut do not enter this boundary and are excluded from these counters. A Rust-selected full WPT or framework run therefore does not establish native coverage by itself. The dedicated packed Vitest fixture requires actual native execution as well as a counted surrogate fallback.

`bun run --cwd packages/html-parser build` builds a release addon for the compiler's host target and packages it alongside ESM/CommonJS loaders and declarations. Both module formats share the same binding and counters. This initial package contains the built host binary; release distribution across OS, architecture and Linux libc targets remains outstanding. Explicit selection on an unsupported target reports addon_unavailable. The build records compiler, target and Node-API level. Turbo native artifact caching is disabled because host/compiler/libc identity is not yet represented in portable cache keys; Cargo still caches compilation incrementally. Node-API is an ABI boundary, not a guarantee that one binary runs on every OS or architecture.

`bun run conformance:native` runs the pinned full-document html5lib tree-construction data against the native and TypeScript parsers, retaining fixture hashes, shared failures, improvements and exclusions. It does not qualify fragment contexts or parse-error counts. November 6 qualification executes 3,464 native trials from 62 files with no boundary failures or regressions against the 3,219 reference-passing trials. Rust passes 3,267, including 48 improvements; 197 failures are shared and 206 fragment cases are excluded. These are parser-tree counts, separate from full-corpus WPT assertion parity. The archived initial JSON baseline is slower than TypeScript. Compact transport replaces that inflated transfer representation; it must be measured independently before claiming an advantage.

Compact wire version two has an eight-word header, twelve-word node records, child-slot and seven-word attribute sections, and UTF-16 string spans. Leaf doctype records reuse ownership fields for public/system identifier spans. The decoder rejects unknown versions, kinds and namespaces, overflowing or truncated sections, split surrogate pairs, invalid template/form slots, multiple parents and cycles. Shared and resizable integer storage is unsupported. The public `parseHTML` result remains the version-one object snapshot type; its semantic authority is also used by `htmlSnapshotSchema`. Native range-limit InvalidArg errors become invalid_request Results; unexpected native exceptions propagate. Kernel Rust unit tests run with the package's normal test command. Native build, lint and test Turbo tasks bypass host-dependent result caching; Cargo remains incremental.

`decodeCompactSnapshot` and `compactSnapshotSchema` expose the complete decoding operation and its storage-shape schema for adapters. The decoder performs semantic bounds and ownership checks beyond the shape schema. Object schemas use a typed extension of the [public Zod core interpreter](https://zod.dev/packages/core), preserving non-throwing parsing without generating functions or changing shared Zod configuration. The no-eval contract observes real installed-package parsing in a subprocess.

The final compact kernel reduces the checked end-to-end parsing workload by about 33% relative to the archived JSON kernel and payload bytes by about 58.5%. It remains 14–36% slower than TypeScript on those fixtures, so it stays explicitly selected. Native encoding/transfer cost increases; total boundary work falls through cheaper decoding and validation. See `docs/qualification.md` for exact scopes and source/package hashes.

The arena retains html5ever's inline/shared tendrils, interned namespace atoms and owned Attribute records through the compact encoding pass. Text merging remains copy-on-write; recovery appends only missing expanded attribute names. The encoder borrows those fields into its existing deduplicated string pool, avoiding intermediate String and attribute-vector copies. Transport version, validation, Node-API ownership and parser-selection defaults remain unchanged.

`parseHTMLArena` accepts the same validated request and typed failure contract as `parseHTML`, but returns an opaque `HTMLArena` with checked semantic reads over fresh native-owned storage. Its node/edge indices must be integers within the arena bounds; invalid required reads throw an invariant error, while absent optional child reads return undefined. The backing words never escape. Returned attributes and `snapshot()` results are independently mutable copies; the arena prototype is frozen. The DOM adapter can allocate canonical records directly without first allocating the full object snapshot. This changes neither wire format nor fallback/counter policy.

The DOM adapter admits a private native arena only after eligible input recurs. At most eight source keys/checked arenas share an aggregate budget of 4,194,304 markup code units and 131,072 arena slots; individual inputs remain limited to 1,048,576 units and 32,768 slots. A small linear LRU avoids hashing entire unique sources. Every use allocates independent canonical raw records. Keys include scripting mode, and capability fallbacks run before reuse. Genuinely unique input, evicted source keys and over-budget input keep actual native execution. `parseHTML` and `parseHTMLArena` themselves remain uncached: the public invocation counter reports actual calls, including the reduction to two calls across repeated DOM constructions. Warm arena reuse is not fresh Rust parser throughput. Closed/released-window probes verify that cached wire storage owns no public records.

The CommonJS boundary bundles its validation implementation to reduce first-call module loading. Neverthrow stays external: exported Result helpers and ResultAsync retain the installed shared package identity. Interpreted schemas preserve the no-eval contract, native/fallback counters still describe actual work, and public parse operations remain uncached.
