# @run-dom/dom

`createWindow(markup)` parses HTML with script execution disabled. It returns the Window, a serializer for its current document, and a source-location lookup. Pass `{ markup, includeNodeLocations: true }` to retain the parser’s source offsets. Options also support `beforeParse` and explicit VM script modes. A host-supplied script loader handles classic script requests, while the Window owns parser order, script events, and cancellation. A host-supplied request function carries asynchronous XMLHttpRequest traffic. The Window owns its request state, progress events, and response views. `createDocumentFragment(markup)` uses a shared owner document with no browsing context. HTML and XML share the same raw tree. parse5 handles HTML and Saxes handles XML documents and contextual fragments. XML rejects malformed markup and preserves in-scope namespace bindings for fragments. Like the pinned jsdom version, XML document parsing supports simple double-quoted internal entity declarations as literal substitutions. External entities are never fetched. Window-local wrappers expose that tree and are allocated on first access.

```ts
import { createWindow } from "@run-dom/dom";
const { window, serialize } = createWindow("<p>Hello</p>");
console.log(serialize());
window.close();
```

The CommonJS build compacts syntax and whitespace and ships a linked source map. It preserves interface constructor names, which consumers can observe through `constructor.name`. A separately packed CSS runtime bundles the pinned toolchain while retaining lazy initialization per capability. It minifies internal identifiers and explicitly preserves the exposed declaration constructor name. Its build adapter shares the declared color backend across direct and declaration-parser requests without changing installed reference dependencies. CommonJS dependency loading uses the installed artifact URL, so it does not depend on the producer checkout.

Window text encoding uses the same codec as the Node facade’s markup decoder. `TextEncoder.encode()` and `TextEncoderStream` allocate output bytes in the Window realm. Each decoder retains independent state across chunks. Text streams preserve split surrogate pairs and byte sequences, BOM and fatal-error settings, backpressure, and cancellation. Their readable and writable endpoints use Node’s stream implementations; complete stream realm isolation remains pending.

Window message channels queue messages until the receiving port starts and support ArrayBuffer transfer. The transport uses Node’s structured clone. Scripted receivers get Window-local prototypes for cloned JavaScript objects and event interfaces, while host-backed objects such as Blob retain their native prototypes. Closing the Window closes its channels.

Selectors use private tree state and support compound matching. A bounded Window-local cache retains compiled predicates, while every evaluation reads current state. Scope-dependent predicates remain tied to their own roots. Selector APIs enforce required arguments and CSS identifier preprocessing. Relational selectors anchor their relative paths without narrowing ordinary complex selectors nested in :is() or :not(). Placeholder, checked-option, range, default-selection, and indeterminate matching reflect current control state. Forgiving :is()/:where() branches contain malformed or unsupported selectors; selector feature queries still reject invalid branches. Type selectors accept wildcard and empty namespace qualifiers. Typed sibling selectors count by namespace and local name. Attribute selectors accept an empty namespace qualifier and wildcard namespace presence and value checks. Simple tag, ID, class, and universal selectors keep a direct path. `querySelectorAll()` returns a fresh static NodeList. Private immutable vectors can be reused through bounded weak entries only for tree-dependent selectors with matching root, owner and mutation generation; live predicates bypass reuse. NodeList and HTMLCollection have separate branded interfaces and native realm iterators. Live descendant lists follow destination revisions after adoption while retaining their creation-time tag-name matching rule. A bounded candidate index narrows repeated subtree searches while predicates still read current state. Tree and attribute mutations invalidate the view; ambiguous selectors and oversized indices use ordinary traversal. Indexed node references are weak, including across adoption. Contextual HTML replacement is available through `innerHTML` and `outerHTML`. Linked and inline stylesheets support basic author cascade, computed styles, and inline declaration reflection. Loaded sheets retain their detected encoding for nested imports and imports added later through CSSOM; imported sheets keep a null ownerNode while retaining their resource initiator. Documents and shadow roots expose their attached sheets through stable live stylesheet lists. Parsed style, media, supports, import, and font-face rules use their Window’s CSSOM prototypes. Media and supports groups expose live rule lists. Nested insertions and deletions affect computed styles when the group condition matches. Assigning a supported selector list to a style rule updates both its serialization and its computed-style matching. Computed styles resolve custom properties against the element’s cascade, including inherited values and `var()` fallbacks. They reuse stylesheet discovery while reading current CSSOM, adopted-sheet, and interactive state. A bounded private cache reuses computed values after fresh cascade matching and dependency comparison, including inherited values, viewport/base dependencies, and target-dependent SVG paint. Returned declarations retain separate readonly snapshots and indexed entries. Their map views share completed private entries until iteration or mutation requires independent native storage; cached source maps never escape. Foreground normalization finishes before retention so repeated reads do not trigger copies. Eviction or oversized style blocks change reuse alone, preserving computed output. Feature queries share the declaration parser’s supported properties and values. System colors resolve through a deterministic light/dark palette at computation, including color-mix() and inherited SVG paints. Native controls use matching palette defaults. Modern color functions retain validated specified syntax and respond to later scheme changes. Font-size keywords compute to pixels, while font weights and widths normalize to computed numeric values, and supported font features inherit according to the pinned property metadata. Stylesheets expose the same live rule list through `rules` and `cssRules`. Legacy `addRule()` and `removeRule()` edit that list through the stylesheet’s normal mutation path. CSSStyleRule exposes ordered nested style/group rules and CSSNestedDeclarations, stable live child lists, declaration ownership, and live selector edits. Layer order follows current stylesheet/CSSOM order, with nested and anonymous layers, reversed important precedence and author rollback. Same-text style source mutations rebuild edited CSSOM while held old rule graphs remain coherent. Borrowed grouping methods allocate child rules through the receiver Window and report DOM exceptions through the invoking Window. Container evaluation, pseudo-element computed styles, full scoped-selector boundaries, layer ordering for named resources and complete CSS compatibility remain unfinished.

Document XPath methods use the XPath 1.0 evaluator on existing DOM nodes. XPath results support scalars, node snapshots, and iterators that invalidate on document mutation. A bounded Window-local cache reuses parsed expressions while evaluation reads the current DOM and resolver.

HTML document-relative URLs use the owning document’s base and encoding, including after adoption across Windows. Native URL parsing handles UTF documents; legacy query encoding loads WHATWG URL algorithms on demand. URL paths and fragments remain UTF-8, and the Window’s `URL` constructor always uses UTF-8.

Document titles read and update the title element in HTML and SVG documents. HTML title and script elements expose direct child text through their `text` properties.
