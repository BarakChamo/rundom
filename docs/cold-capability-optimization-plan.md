# Cold capability loading and process history

First-use role CPU samples attribute substantial self time to CSS bundle compilation/evaluation, before useful DOM work. The current lazy getters delay initialization but keep all four capabilities in one 1.4 MB CommonJS compilation unit. Test separate private grammar, selector, declaration and color artifacts while keeping the current CSS facade, pinned dependencies, package export conditions and single declared color backend. Share grammar and color dependencies across artifacts rather than embedding independent copies. Public declarations, prototypes, accessors, reflection, parsing and errors must retain their existing contracts.

Before changing the build, preserve the fully measured query/ownership checkpoint. A meaningful loading contract uses a fresh process: complex selector matching must work while color/declaration implementation modules remain unloaded; the first computed-style use must produce the same output and load the needed capabilities. Repeated access must retain capability identities. Test actual built output, then independently packed consumers. Existing CSS grammar/property/interface/realm tests cover behavior; full default/native API, type and four-pool Vitest gates plus selected assertion replay qualify a retained change.

Measure clean cache-disabled loading, first use, warm reads/mutations/roles, small/large parsing, long/small lists, interactions and complete framework cost against the immutable checkpoint. Nine rotated fresh processes are the timing minimum. Separate forced-GC lifetime and CPU/allocation probes from latency. Total artifact bytes, live/released heap and loaded module count expose splitting costs. Reject cold wins that merely move work into setup or cause material warm/runtime/memory regressions.

Explicit Node module compile caching is a separate configuration experiment, not a library-side process setting. Measure disabled, empty-cache and disk-primed configurations for every pinned provider, recording initial population, exit-time writes and cache bytes. Process history is also separate: close a seed Window that used additional documents, custom elements or shadow roots, then measure ordinary fresh Windows. Realm-local capability switches require measurable benefit and cross-realm/borrowed-method/adoption tests before implementation.

## Decision

Both layouts are rejected as defaults; the qualified single bundled runtime is restored. Four separate capabilities accept 441 timing trials; separate grammar/selector artifacts plus a combined declaration/color artifact accept 306. All use nine rotated fresh processes and nine batches, and both candidates pass 1,451 ordinary tests including the built-artifact loading example. Complex-selector first use improves about 8 ms. Several warm style/role/parse controls are worse or mixed, and the separate frozen React comparison accepts 18 trials with complete-process medians 612.60 → 619.66 ms, test bodies 120.78 → 116.69 ms and worker RSS 193.27 → 193.14 MiB. This does not establish a useful complete-run improvement. No public build-profile switch is added. Source alternatives, loading example, frozen cohorts LAAVJh/S2MBo6 and complete reports remain under `.cache/qualification/css-*`.

Current host observations include substantial background application CPU; timings remain exploratory and comparisons are paired within a run. Absolute medians from earlier host periods cannot substitute for current controls. The source-level realm-local capability experiment is independent of these rejected build layouts.
