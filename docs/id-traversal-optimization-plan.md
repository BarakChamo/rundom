# ID lookup and mutation traversal optimization batch

Reduce repeated discovery/allocation during long-list reconciliation while preserving current Document/DocumentFragment ID semantics. The boundary is private raw-tree lookup in the DOM workspace; no public exports, parser defaults, exceptions or transport change. Baseline is the qualified S0wQID runtime. Derived state must remain weak and rebuildable, and cannot retain detached/adopted trees or change duplicate-ID order.

Pin public examples before implementation: duplicate IDs after edits/reorder/removal; ID changes through Attr and namespace APIs; unrelated text/class/data changes; cross-window adoption and borrowed methods; shadow/template/fragment boundaries; live document parsing and XML; resource cleanup reentering ID lookup after detachment. The cleanup case must reject a stale warmed ID index. Owned tests use the installed facade; no counters or cache internals become public.

First separate the ID index generation from unrelated mutations, conservatively invalidating unknown operations and element topology changes. Invalidate before reentrant resource cleanup. Then evaluate direct raw-tree lookup without per-node generator results, retaining ordinary tree order and root boundaries. Existing mutation/callback traversals keep their semantics unless independently proven equivalent.

After the owned gate, freeze a substantial candidate and run nine rotated fresh-process trials against S0wQID and the pinned competitors. Cover small/large reconciliation, ordinary ID hits/misses, mutation-heavy queries, text writes, interactions, parsing/traversal, roles and VM construction. Profile CPU/allocation and diagnostic lifetime separately after timing. Reject regressions rather than selecting only favorable rows. A retained runtime receives fresh owned/native/API/packed-runner gates, full selected WPT/local/legacy replay, source archives and evidence hashes. Update the performance findings, package contract and guide with actual results and remaining costs.

The retained candidate additionally marks only the old/new ID keys or IDs in an affected ordinary subtree as dirty. A read repairs that key from current tree order. More than 128 outstanding keys discards the derived map and returns to ordinary admission; parser/unknown revisions remain conservative full invalidations. Invalidation after complete child replacement prevents an intermediate cleanup lookup from being published as the final result. Weak node entries and the existing ownership boundary remain intact.

The batch closes with 945 accepted matrix trials, full unchanged selected assertions, separate interaction warmup controls, allocation/lifetime observations and evidence hashes. The retained implementation has a live-index memory tradeoff, not a retention win. A direct reference probe records the pre-existing intermediate frame-cleanup visibility mismatch during replacement separately from the corrected detached-ID case and final-result invalidation. Future changes to replacement transaction order must preserve Range/iterator/observer/reentrant insertion behavior and receive their own reference examples and complete qualification.
