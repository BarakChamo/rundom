# Completed-frame and parse-reuse optimization batch

Reduce real default-environment work while preserving the selected jsdom contract. The fixed baseline is `.cache/performance-lab-z2miUa`; no active goal is created. Use one substantial candidate followed by serial matched measurements and a full compatibility replay.

## Boundaries and acceptance examples

1. The laboratory owns equal-work scenarios and independent-document worker experiments. Add unique HTML, four rotating HTML shells and complete per-row reads to separate raw parsing, cache warmth and materialization. Counters continue across first use/warmup/batches. Real-candidate integration tests reject reused wrong markup and skipped text/attribute reads. Prepare the former runtime with the new rig before comparing it.
2. The stylesheet engine owns completed private frames. Prove tree-only flat author rules before skipping cascade reconstruction. The complete style mutation revision, linked stylesheet generation, receiver document, environment and capability exposure must remain valid. A public stylesheet escape closes reuse before CSSOM mutation can occur. Inline declaration provenance remains on the complete path; reflected-attribute equality alone is not sufficient proof. Media/nested/live-selector/shadow/automatic-direction cases stay on the complete path. Fresh public computed views and old snapshots remain independent.
3. **Rejected after measurement:** the eight-entry template-cache experiment improved rotating shells but reduced unique-input worker throughput. Its frozen build remains hRSUzs; production retains the existing single-entry cache. Inactive TypeScript parsing owns byte/node-bounded template reuse. Evaluate multiple recurring shells against TurboDOM's 64-entry immutable-buffer LRU; retain the current form/source-location/active/native exclusions. Templates never escape and every document remains independently mutable. Admission, eviction, malformed input and multi-window lifetime examples precede implementation. Entry count alone is not a memory budget.
4. Evaluate Rust end-to-end and native/decode/materialization attribution using actual native-call counters. Evaluate 1/2/4 worker lanes with startup, warmed task work, complete elapsed work and process memory separately. Worker warmth is explicit; independent documents can run concurrently, one mutable synchronous Window cannot be split into asynchronous operations without changing its contract.

## Execution and gates

First extend/check the rig and freeze the same baseline artifacts under it. Measure baseline CSS reads, construction, Rust parsing and worker behavior serially; source inspection may run concurrently with nothing that adds measurement contention. Then implement frame and parse changes with mutation/adoption/CSSOM/snapshot/ownership contracts. Run the repository gate, both parser paths, packed API/types/all Vitest pools and native coverage. Freeze once for the full selected WPT replay. Measure CPU/allocation separately from uninstrumented timings and all correctness jobs. Keep failed probes, literal assertion names, harness exceptions and unmatched records visible. Shared-host timing is exploratory.

Update `optimization-opportunities.md`, `turbodom-performance.md`, package documentation and the project guide where ownership or commands change. No new public facade API or parser-selection default is required. Browser exceptions and typed native failures retain their existing contracts. Do not move cold work into hidden warmup, share mutable public constructors, or return cached public NodeLists/computed declarations.
