# Construction and native compiler optimization batch

Reduce independent Window construction and cold capabilities while preserving per-window constructor/prototype identity, public descriptors, event behavior, VM identity and cleanup. Baseline: the fully qualified FleHh7 runtime. No benchmark overlaps compilation, tests or a profiler.

First use readable-line Inspector attribution to locate remaining Window setup costs. Evaluate the existing initialization algorithm and native bulk descriptor operations before changing ownership or adding lazy proxies. Pin descriptor, constructor, subclass and script-mode behavior through public tests; retain the full path when a capability's initialization is observable. Update the DOM README and project guide if construction changes.

In parallel with source inspection, build an isolated Rust thin-LTO/codegen-units=1 artifact without changing production binaries. Compare the raw native call plus public compact validation in nine rotated fresh processes on small/large HTML, checking exact snapshots before timing. Record cold loading, binary bytes, compiler identity and the distinction from full DOM timing. If promising, qualify the compiler change through native trees, both parser paths and packed consumers, then measure complete construction with all providers. Transport, typed failures and backend-selection defaults stay unchanged.

Cold CSS setup remains a separate measured opportunity. Shared public accessor functions and multi-entry parse templates remain rejected. A new experiment must reduce total import/setup/first-use cost rather than move it into warmup. The batch ends with a frozen substantial candidate, the full selected corpus where the default runtime changes, serial provider/framework measurements and source/evidence hashes. Keep rejected experiments and failures visible.

The retained implementation is allocation with the public prototype before member initialization. Before selecting further work, cross-check a stratified matrix: long-list reconciliation and static views, dispersed edits/replacement, real interaction callbacks and live CSS state, deep event dispatch/default actions, repeated writes, query invalidation, observers, role/style reads, native-selected interaction state and isolated VM construction. The 36-scenario rig keeps these as independently verified operations. Profile large-list, interaction and role costs separately rather than generalizing constructor attribution to them. Full compatibility qualification and lifetime observations close this batch; compiler-only LTO experiments remain unshipped unless a complete runtime benefit is established.
