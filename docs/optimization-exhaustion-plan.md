# Material-gap optimization sweep

Only existing canonical workloads with accepted RunDOM–TurboDOM deficits above 5 ms are optimization targets. Smaller/failed/previously winning cases are correctness or cost-shifting controls. Baseline source/runtime is sealed deMMKD (`.cache/qualification/material-gap-sealed-manifest.json`). No source changes are present at the start of this sweep.

## Completion contract

Each item below ends with an implemented measured experiment, compatibility/ownership checks and a retained or rejected decision. Rejected code is removed from production and its source/results remain archived. A cost hypothesis contradicted by profiling is closed with the exact evidence, rather than manufacturing a change. Completing this finite exploration list does not mean every possible DOM optimization has been exhausted or that all TurboDOM gaps disappeared. One final combined source must pass full default/native/API/types/native-corpus/packed-Vitest/selected-assertion gates and a broad serial matched matrix. Timing, profiling, builds and correctness run in disjoint phases.

No public API/default parser change is planned. Every path must preserve per-window constructors/prototypes, independent document and Attr identity, mutation ordering, first-match IDs, namespaces, inert templates, adoption, active parsing and retained closed handles. Native storage remains validated and native/fallback counters remain truthful. Record first-use, warm work, source-key/cache retention, native/external storage and real framework results separately.

## Batch A — private data paths

1. **ID-index admission.** Existing code scans the first three lookups and builds a complete map on the fourth. Test cost-aware/bounded partial admission against this real baseline. Cover early/late/missing/duplicate IDs, repeated/random reads, document rewrite, renaming/removal/adoption, callbacks and close/rebuild. Public boundary: Document.getElementById; no new errors/API. Tests: existing ID mutation/ownership contracts plus mixed-prefix/miss cases. Retain only broad constructor/mutation gains, not a specially placed fixture ID.
2. **Private-template copying.** Replace generic live-tree clone bookkeeping only at the unexposed immutable parse-template boundary. Evaluate a depth-first copier with reusable O(depth) traversal arrays, avoiding a work-record object per parent and mutable control/custom-state lookups that private parser templates do not own. General public clone/import/range paths remain unchanged. Check deep/wide trees, SVG/MathML, doctype, nested template content, character data and independent writes/serialization.
3. **Attribute copy-on-write.** Share only never-exposed private attribute blocks, forking one element's complete block before a mutation or public Attr exposure. Audit every writer, NamedNodeMap path, borrowed/adopted operations and parse5 attribute adoption. There must be no document-wide promotion. Extend to native arena attribute decoding only if the same ownership barrier is sound. Tests cover retained Attr identity, namespace edits, parser writes, attribute-node attachment/removal, reactions and MutationObserver old values.
4. **Native bulk materialization.** Profile actual unique input and warmed checked arenas separately. Evaluate a bounded traversal/copy operation inside the arena owner, avoiding repeated public getter validation and metadata projection while retaining fresh raw/public trees and checked Unicode/ownership. Keep public checked indexed reads and uncached parser entry points intact. Native/default gates and explicit invocation contracts are required.
   Follow-up: compare retaining a never-exposed materialized native template and making independent eager copies, discarding its arena after admission. This preserves the second actual native parse rule and tests repeated decoding against a measured heap/external-memory tradeoff.
5. **Native ownership validation.** Determine whether ownership checking through public checked arena getters repeats already-proven storage bounds. If material, use an internal storage reader whose inputs/indices are proven by the existing validator; retain every malformed-buffer/edge/Unicode rejection and no-eval contract. No unchecked public storage escape or weaker validation is allowed.

## Batch B — realm and public-view construction

6. **Per-window interface assembly.** Attribute class/prototype/global construction using current and existing phase probes. Evaluate a coherent family of leaf HTML-interface factories with distinct public objects/functions and identical names/descriptors/prototype relationships. Constructor/custom-element behavior and VM realms remain contracts. Do not repeat rejected global descriptor batching or one-step initial shape changes. Compare eight empty windows and first/full use, not construction alone.
7. **Role-query snapshot publication.** Refresh role CPU/allocation evidence. Evaluate the dominant measured publication/metadata path, potentially opaque view records and handler reuse behind fresh CSS snapshots. Preserve public fresh identity, readonly behavior, reflection, expandos, borrowed methods and old snapshots across mutation. Keep selector/live-state semantics and the full CSS cascade. Test real repeated interactions/long-list React contracts and all Vitest pools.

8. **Wrapper constructor dispatch.** Compare the existing tag branch chain with a private lookup of canonical per-window constructors. Keep ordinary construction, dynamic superclass behavior, private initialization and custom-element contracts intact. Reject the lookup if traversal/update wins fail to offset startup/allocation costs.

The role family also evaluated scalar computed reads outside closure-creating shorthand/color serialization. This is a measured follow-up, not a new property cache.
