# Collection and query optimization batch

The performance laboratory identifies static NodeList construction and repeated query matching as primary avoidable costs. Deliver a coherent change to collection representation and immutable query work, then measure the actual runner. The public API remains the DOM/HTML collection interfaces. The target is reduced allocation and repeated query cost while retaining fresh snapshot identity, ordinary prototype overrides and complete indexed/named reflection behavior.

## Contracts before implementation

Add public examples for fresh query snapshots, retained contents after insert/remove, stable element identity, item boundaries, iteration through every element, expando writes, strict indexed deletion, descriptors/ownKeys, inherited method overrides, freeze/preventExtensions, and borrowed methods across windows. Include array-index boundaries near 2^32 and distinct HTMLCollection/NodeList prototype surfaces. Existing upstream collection failures must remain visible and be repaired only by standards behavior.

Class membership cases include exact words, prefixes/suffixes, overlapping matches, empty attributes, every ASCII whitespace boundary, vertical tab and NBSP, Unicode/escaped selectors, XML/namespace distinctions, and direct/classList attribute mutation. Preserve private raw-state access under overridden public getters. Tests precede replacement of splitting with allocation-free membership or immutable string-derived work.

Any query result reuse needs positive eligibility from selector syntax, receiver/root identity, current document/realm and an authoritative mutation generation. Dynamic control/focus/defined/custom-state/target predicates bypass reuse until their full inputs are keyed. Cross-realm adoption and parser/reentrant mutations must invalidate or bypass. Cache entries contain bounded selector strings and weak roots/results; they must not retain detached windows or adopted wrappers. Losing a cache is always a complete ordinary computation. No return of a shared mutable public NodeList.

## Execution batches

1. **Collection contracts and representation:** extend the public tests and equal-work rig with static-list full iteration/reflection/identity/invalidation. Implement cheap fresh static views using the indexed-property semantics already required for live views, with no extra public prototype layer. Separate HTMLCollection's interface surface from NodeList where necessary. Run the owned/API/packed-type/runner gates and selected collection WPT cases.
2. **Query work:** remove repeated primitive class tokenization and evaluate bounded weak immutable result-vector reuse. Prefer exact strings and existing ownership authority over a second mutation system. Profile and test cache hits, class edits, topology edits, registry/control state, scope, XML and adoption. Keep negative outcomes and reject memory regressions. Complete the local/CSS and full selected WPT replay against one frozen build before claiming compatibility preservation.
3. **Matched performance:** freeze candidate and before artifacts, then run nine rotated serial fresh-process trials after all correctness jobs stop. Increase warmup/operations for short batches. Include length-only, full iteration, cache invalidation, many windows, CSS reads and the checked React runner. Report allocation and retained-memory changes as separate observations. Confirm on an isolated host before certifying speed ratios. Continue to first-use CSS and computed-view costs based on remaining profiles; no automatic Rust or parallel rewrite.

The handoff's rejected weak static-match cache is not evidence that a result-vector cache will help. This batch must show where traversal, tokenization and snapshot construction are actually removed and confirm the gain in framework work. The goal remains faster than Happy DOM with complete drop-in semantics; an isolated query win does not complete it.

## Implementation checkpoint

The collection view, allocation-free primitive class predicate and bounded weak query-result reuse are implemented. The release gate passes 1,399 owned tests. Upstream collection fixtures exposed two indexing/adoption cases beyond the initial owned examples; retain the added numeric-name, foreign-revision and HTML/XML retained matching regressions. The final full replay uses `collection-case-checkpoint-full`, independently frozen from mutable workspace builds. Earlier collection checkpoints retain their actual failures or explicit supersession metadata.

Matched measurement compares the original runtime, repackaged with the current probes, with the final candidate. Five read/event scenarios use 8,192 operations per batch; iteration, snapshot and invalidation scenarios use 256; creation/parsing uses eight. Every combination has nine rotated fresh-process trials and five measured batches. Failed provider screens remain evidence, with no assigned speed ratio. Separate lifetime passes cover 1/8/32 windows, followed by before/after CPU and allocation attribution. See the results page for completed observations; queued jobs are not results.
