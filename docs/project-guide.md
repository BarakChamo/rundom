# Project guide

Template-Version: 1

## Stack and workspace map

Use Node 24 for consumers, Bun 1.4.4 for installation and build commands, TypeScript 7.0.2 with strict settings, and Turborepo 2.11.10 for task orchestration. Rust uses stable with MSRV 1.89, Cargo, rustfmt, and Clippy. [The root README](../README.md) lists normal commands.

| Workspace                                                   | Contract                                                                  |
| ----------------------------------------------------------- | ------------------------------------------------------------------------- |
| [`@run-dom/dom`](../packages/dom/README.md)                 | Window-local DOM interfaces and HTML parsing.                             |
| [`@run-dom/jsdom`](../packages/jsdom/README.md)             | Synchronous Node facade. It imports only the public DOM entry point.      |
| [`run-dom-core`](../crates/dom-core/README.md)              | Canonical Rust topology used by the HTML sink; Cargo task workspace.      |
| [`@run-dom/html-parser`](../packages/html-parser/README.md) | Node-API loading, compact transport validation and typed native failures. |
| [`run-dom-html-parser`](../crates/html-parser/README.md)    | html5ever arena sink and compact native encoder.                          |

Turbo caches the TypeScript artifacts and successful task results. The DOM build emits a separate CommonJS CSS runtime, with lazy getters for the pinned parser, selector engine, declaration implementation, and color resolver. Static CommonJS requests preserve dependency export conditions. The package-local CSS build adapter resolves color imports to the DOM workspace’s declared public color entry, avoiding a second transitive color runtime inside the production artifact without modifying installed reference dependencies. Its script participates in Turbo’s ordinary package inputs and the DOM lint command. Each CommonJS build derives import.meta.url from its installed artifact using Bun’s define/banner options; producer source paths must not determine dependency or worker loading. Root compiler options participate in task hashes. Rust tasks use Cargo's platform-specific local compilation cache. Turbo artifact caching for Cargo is disabled until the shipped native outputs and toolchain/platform key are defined. The full local gate is `bun run check`. To force fresh Turbo results, run `bunx --no-install turbo run build typecheck lint test --force` after the formatting check.

## Architecture and state

Node runs consumer JavaScript. The DOM's canonical TypeScript state uses the parse5 tree adapter. HTML is parsed by parse5. XML is parsed by Saxes into the same tree shape. Wrappers are allocated on demand and retain stable identity per tree node. Window-local constructors are separate across windows. XML serialization delegates namespace repair and well-formedness to the pinned w3c-xmlserializer dependency through private raw-node views. Child views are memoized only within one serialization call. XML innerHTML/outerHTML getters require well-formed output and translate declared failures into the owning Window’s InvalidStateError; XMLSerializer and facade serialization use the permissive contract. HTML serialization retains the parse5 path. Internal tree algorithms use raw nodes, including option membership, to avoid invoking replaceable properties. Option membership is derived from topology and invalidated by a structural revision.

Public high-resolution timestamps share the non-isolated Window’s 100 µs relative precision across performance.now(), events, animation frames, and resource timing. This preserves ordering between adjacent reads without exposing a finer clock through another API.

Form range pseudo-classes share numeric constraints and validation candidacy with controls. Default selection reads content attributes, while checkedness and indeterminateness read live private state; radio indeterminateness uses current group membership. These predicates are reevaluated inside relational selectors. Readonly applicability is type-specific and distinct from disabled state, validation candidacy, and the checkbox/radio/file required rules. Validation, placeholders, and successful-control submission read private input/textarea values; textarea defaults use direct child text. Literal and escaped form-state selectors route through the same live predicates. Document design mode and contenteditable inheritance determine editing state without overriding input/textarea mutability. Label activation resolves its control after listeners and respects intrinsic event cancellation. Event cancellation is shared private state across Window event classes, independent of replaceable public getters. Radio insertion snapshots checked defaults across all inserted roots before normalization; detached controls without a form preserve independent checked defaults until connection or form association. Connected explicit form associations resolve IDs within the current tree root; disconnected controls fall back to an ancestor form, including in live collections. Readonly presence bars constraint validation on inputs even where it does not change mutability, matching the checked browser behavior. Input states without required semantics match :optional.

Document focus uses one discriminated state for a focused element or viewport. Focus transitions clear the old state before blur dispatch, revalidate after callbacks, and project child browsing-context focus into embedding frames. Focusability follows assigned slots and excludes suppressed light and fallback content.

Live HTML parsing validates host-including topology before attaching parser nodes. Invalid cyclic or extra document-element insertions are dropped while parsing continues into the detached element. Defined custom elements construct before token attributes and connection; template contents remain inert. Foster parenting into a template element redirects to its contents.

Every exposed HTML interface delegates external construction to one HTML-constructor operation, carrying the active interface explicitly. Its private-token allocation path still calls the native superclass directly. Native prototype lookup is derived lazily from the existing wrapper dispatch rather than a second tag-to-interface table. A native Object-construction probe preserves the single observable new-target prototype access and obtains the correct fallback realm through nested proxies and bound functions.

Copy initialization uses the destination document’s realm before custom upgrades, including imports, adopted-node clones, and Range copies. Failed upgrade state preserves any prototype already installed by super. After a blocking HTML parser resource has suspended execution, subsequent eligible scripts yield through a microtask boundary; initial inline execution remains synchronous.

Document factories and DOMImplementation methods dispatch through captured intrinsic factories in the receiver's realm, independently of replaceable public prototypes. Fragment parsing establishes document ownership and creation realms before insertion, including text/comments in adopted shadow hosts. Ordinary HTML replacement collects a bounded set of possible ID changes and capability flags at parse time. The final tree still determines the order of observable work. Resource cleanup that can reenter and cross-realm replacement retain the full traversal. Range content copying reads shared private boundary records so borrowed methods do not depend on another class's native private-field brand.

Document's legacy named wrapper is installed by the Node constructor before Document initializes its private fields. The public proxy therefore owns the private fields and remains the canonical node wrapper; methods are never bound to a hidden target. Names derive from ordinary document descendants and relevant attributes, with weak node references. A separate named-property generation changes only for potentially relevant structural/name/ID edits; ordinary insertion checks the changed subtree rather than rescanning the document on each public access. Existing own properties take precedence; inherited built-ins may be shadowed. Duplicate names return stable live collections, weakly cached with finalizer cleanup. Window global members are installed on the actual global, while EventTarget methods remain inherited and preserve function identity. Bare VM event calls normalize null/undefined receivers at the event boundary. Window lifecycle operations validate receiver ownership before closing or stopping resources. Complete WindowProxy exotic behavior remains unfinished; ECMAScript Object/Reflect intrinsics are not substituted.

Interface and namespace bindings are non-enumerable, including lazy constructors and their replacements. The historical XPathException factory retains pinned jsdom's enumerable descriptor. Isolated Window, DOM/EventTarget and Event prototype roots use that Window's intrinsic Object/Function chain; this does not establish complete native-function or host-backed-object realm isolation. Shadow-root allocation follows the host's current node document while preserving the host wrapper after adoption.

Custom-element reactions share weak per-element FIFOs across Window operations. A subtree's eligible callbacks are queued before any callback runs, and nested operations drain the affected element's earlier work before newly enqueued callbacks. Absent/unobserved callbacks do not create a delivery opportunity. Upgrade attributes and initial connection eligibility are captured before construction; failure discards queued upgrade callbacks. Author exceptions are reported without suppressing other queued work. Unannotated attribute operations use a microtask backup path. Range/Selection removals and disconnected fragment/shadow upgrades use the same delivery boundary. Inert template owner documents do not acquire a registry through explicit upgrade.

An explicitly opened HTML document has one incremental parse5 write session, preserving tokenizer state, open elements and exposed node identity across chunks and EOF. Future chunks receive form/details/frame/stylesheet tracking even when the first chunk contains no such tokens. No duplicate concatenated markup buffer is retained. Writing after document close starts a new parser stream. Explicit streaming is independently checked against Chromium.

ElementInternals.states lazily returns a stable Window-local CustomStateSet. One weak private store owns membership for both the setlike API and CSS predicates, including across adoption and borrowed methods. State-set handles retain their target while held, and membership remains with a live element after handle collection. Arbitrary DOMString values are allowed; :state() requires one CSS identifier, decoded case-sensitively, with shared matching/serialization validation. Set writes do not reflect attributes or enqueue attribute callbacks. Selector/style matching reads live state without assuming a DOM revision, including relational, nth-of, inherited and shadow-host matching. Each public computed-style declaration reads the current element state. Immutable frames can be reused between reads while their dependencies remain valid. Complete shadow-part styling is still pending.

Variadic append and prepend convert their inputs into one insertion. Document replacement validates the replacement children independently of the old doctype and root. Mutation insertion establishes the complete tree before running a fixed list of post-connection steps in shadow-including tree order. Script child changes run before newly inserted descendants' post-connection steps. Frame getters read the browsing context established by those steps; they do not create one on demand. Form callback eligibility is tracked per document and transferred on custom-element adoption, so a registry in one Window does not enable full-tree parser scans in every Window.

DOM selector predicates, including simple tag, ID, class, and universal predicates, are compiled once per Window into bounded predicate caches. Scope-dependent or escaped selectors use weakly owned per-root caches; XML and HTML remain separate. Each cache retains at most 256 selectors of at most 4096 code units. CSS syntax preprocessing and EOF recovery run through the pinned tokenizer before matching. DOM queries and stylesheet matching contain malformed branches at :is()/:where() boundaries, and discard unsupported branches without weakening strict :not()/:has() parsing. CSS selector feature queries retain strict validation of every branch. Relative selectors inside :has() have an explicit subject anchor while nested ordinary complex selectors retain their own meaning. Heading levels read current shadow-including offsets and reset boundaries. Directionality reads current private control values and first-strong Unicode bidi classes; bidi-js tables load only on first automatic text direction query.

Query candidate indices narrow ordinary-subtree traversal without retaining match results. Positive subject constraints choose tag, ID, class, or attribute buckets, and the existing predicate evaluates each candidate against current state. Tree order and duplicate elimination are preserved. Hints share selector Unicode/EOF preprocessing; ambiguous escaped namespace names fall back to traversal. Each index has at most 32,768 reference entries; a Window retains at most 32 indexed roots and 65,536 entries. Larger or unconstrained queries use linear traversal. Mutation drops the views immediately, arbitrary attribute changes invalidate candidates even when stylesheet discovery need not change, and adopted foreign roots bypass the originating Window’s index. Weak node buckets and weak ordering keys avoid retaining removed subtrees through an adopted root.

Live label lists share a lazily rebuilt association index per tree root. Tree, ID, for, input-type, and form-associated custom-element construction changes invalidate it. The index uses weak control keys and weak label references. Original wrappers adopted into another Window bypass the index because the destination revision is independent.

CSS declaration writes publish the completed block once, after input conversion and before custom element reactions can reenter. CSS-tree parses declaration lists in source order; public cssstyle metadata supplies shorthand dependencies. Important longhands survive later normal shorthands, and mutations dispatch through the declaration's owning interface when methods are borrowed across Windows.

Stylesheet discovery has one weakly owned snapshot per raw scope, keyed by membership and linked-sheet revisions. Ordinary attribute changes still invalidate selector matches without discarding stylesheet discovery. StyleSheetList and computed-style evaluation share the live records. Repeated error-free flat stylesheet syntax can share matched-selector preparation and declaration factories within a Window. Every attached rule has an independent mutable CSSOM view. One private record per rule carries its kind, parent links, and applicable group, selector, and declaration state across borrowed CSSOM operations. The snapshot retains live CSSOM records. A bounded computed-style cache reuses completed document frames when tree and linked-sheet revisions and the captured viewport, base URL, and focus dependencies still match. Exposed and adopted stylesheet paths evaluate current CSSOM state. It compares ordered winning declarations, inherited frame identity, target/ancestor role, user-agent fallbacks, document-root position, and any viewport or base-URL dependencies used by that computation. Selectors with live dependencies outside those checks evaluate afresh. Authored targets can capture cascade and inheritance inputs before resolving values. A deferred view resolves independent properties on access. Dependent reads and enumeration materialize the captured declaration and release the cached recipe. Inputs that could require another live environment read take the eager path. Certified ordinary ancestor frames can supply target declarations with the final foreground, while element-relative SVG paint uses the target cascade. Cached declarations never escape. Target foreground normalization finishes before frame retention. Public computed results are fresh live views that validate the current read context on access; maps and native helper methods never escape. Indexed reflection reads immutable private data, and ordinary expandos stay per-view. Inline and rule declarations retain stable receiver-owned views. Parent frames and element keys are weak. A Window retains at most 128 frames, 8,192 property units, and 262,144 UTF-16 code units; an individual frame over 2,048 units or 32,768 code units is not retained. Validated ancestor hits refresh their position in the shared eviction order because descendants depend on those frames. Cache eviction also removes empty element slots. Large inputs still compute normally. Retention budgets include both winners and computed property values. Large computed custom-property blocks share immutable names and values, with index groups preserving their order among ordinary properties. The frame cache charges shared token storage once while a cached frame references it. An ordinary-document focus check can use ancestor display values from its own cascade while the revisions and native readers remain valid. Reentrant parsing publishes no snapshot after the relevant revisions change. Text and CDATA edits under an HTML-namespace style element invalidate the revision independently of XML prefixes.

CSS feature queries use cssstyle’s public property parser, matching the property interface and patched syntax accepted by declarations. Font inheritance and initial values derive lazily from the same pinned metadata, with explicit computed weight/width normalization. Valid unresolved comparison math is retained for longhands after native validation with representative compatible dimensions. Computed numeric values resolve font and viewport lengths, comparison functions, absolute units, and integer rounding where the property grammar requires it. Public shorthand removal clears expanded longhands in one publication; native setters’ intermediate removals retain their existing internal sequencing. Empty longhand writes still use native setters to invalidate reconstructed shorthands. Absolute font-size keywords use deterministic headless sizes; larger/smaller compute from the parent size.

Modern color serialization follows grammar validation by the declaration parser; a serializer must not repair invalid input into an accepted declaration. A deterministic light/dark system palette resolves keywords at computed-value time, including nested color functions and inherited SVG paints. Native control palette defaults share these values, and author styles can override them. System keywords stay intact in specified declarations so scheme changes remain visible.

CSS nesting uses the pinned parser's public fork to replace style-block dispatch, retaining native tokenization and recovery. Flat sheets keep the original parser; nested blocks and scoped declarations initialize the extension lazily. CSSStyleRule owns its leading declaration block plus an ordered child graph, with CSSNestedDeclarations for later declaration runs and bare group declarations. Shared weak CSSOM records preserve receiver Window factories during borrowed operations, while DOM exceptions belong to the invoking method. Parent selector bindings and specificity are derived from current rule selections without Cartesian expansion or global predicate registries. Anonymous and named layers derive their order per computation from current scoped stylesheets; repeated adopted sheets use their last occurrence. A transient candidate chain resolves author origin/layer rollback and is removed before computed-frame retention. Same-text source mutations carry a weak scalar epoch so CSSOM edits cannot survive source replacement; detached old rule graphs preserve child identity and parent relationships.

Stylesheet source includes both XML Text and CDATA, excluding comments and processing instructions. XML stylesheet discovery compares local names independently of prefixes. Selector specificity uses independently clamped ID, class, and type components; selector-list pseudo-classes use their strongest argument, while `:where()` contributes zero. Inline declarations retain a separate higher score. The raw selector adapter preserves the pinned jsdom `:empty` behavior, which counts nonempty whitespace Text and CDATA as content.

Document-relative URL parsing reads private base and encoding metadata from the node document, including after adoption. The native URL parser handles UTF documents; WHATWG URL algorithms load lazily for legacy query encodings. Frame response decoding has a separate MIME boundary from constructor input: loaded non-XML frame bodies use the headless HTML parser, same-origin HTML inherits the initiating document’s fallback charset (using the final response origin after redirects), and XML and JSON default to UTF-8. XHR text uses standard legacy decoding with BOM precedence. Its final charset is resolved independently of final MIME type, preserving an HTTP charset when the override omits one. Default XML text can use XML declarations. XHR document decoding uses the same pinned html-encoding-sniffer dependency as facade byte input, keeping protocol decisions in the DOM without importing the facade. HTML response metadata lookahead uses the pinned parse5 token and insertion-mode interface. Early declarations can apply before byte 1024; later declarations require in-head parser state. Raw-text meta strings are excluded. This browser-compatible behavior is verified against Chromium 156 and the unchanged XHR charset fixture; the current formal XHR byte-prescan algorithm alone does not reproduce all of those cases. BOMs and valid HTTP charsets bypass lookahead, and no script executes. XHR author headers retain canonical lowercase lookup keys and separate first-spelling metadata. Transport defaults merge case-insensitively before wire-name projection; preflight carries the configured User-Agent. Body union conversion precedes request-state checks, rejects shared memory, and preserves reentrant stringification behavior. Synchronous workers resolve a sibling installed artifact and inherit embedding Node flags and preloads. Resource decoding resolves encoding before stylesheet parsing or classic-script evaluation. Stylesheet state retains detected encoding and a separate import resource initiator so nested CSSOM imports preserve their parent encoding without exposing an owner node. Text codecs own their streaming state and Window-local byte output; Node supplies stream scheduling and endpoints. Complete stream realm isolation is still pending.

The Rust tree is the canonical topology used by the new html5ever sink in `crates/html-parser`. `packages/html-parser` owns the Node-API loader, versioned bulk snapshot and typed boundary. `packages/dom/src/native-parser.ts` materializes private records for explicitly selected inactive document parsing. Browser objects remain TypeScript and the default parser remains parse5. Native invocation/fallback coverage is separate from passing a Rust-selected test run; active parser, XML, fragment and empty-document paths do not enter the kernel. Parser and persistent storage experiments need independent measurements.

Computed style can skip author rules when every selector branch requires a class or ID on the element being styled and none of those keys are present. The index is derived from private rule arrays and weakly owned by them. It covers lists of 24–4,096 rules with at most 8,192 bucket entries. Unindexed rules retain their positions in cascade order. The full matchers still evaluate specificity and live state. Exposed CSSOM, adopted stylesheets, and nested or scoped selector bindings use the full traversal.

The stylesheet parser retains up to 256 immutable snapshots of small flat declaration blocks. A Window tracks up to 192 recent sources of at most 1,536 UTF-16 units through weak syntax references. A surviving reference repopulates the shared 32-entry small-source cache on a miss. Up to eight error-free stylesheet syntax trees between 4,097 and 16,384 UTF-16 units are retained alongside the small-source cache. Large flat blocks can reuse validated snapshots keyed weakly by their private syntax nodes. Empty source skips parsing and keeps an independent CSSOM sheet. Each CSS rule restores its own mutable values, priorities, indexes and border source order. An unescaped ASCII class or ID with no namespace mapping uses the DOM matcher directly with CSS specificity and serialization preserved. Selector compilation retains up to 128 entries per Window state table and up to 128 state-independent entries. The selector cache records whether every branch matched the grammar so a permissive stylesheet parse cannot satisfy a stricter CSSOM setter. Computed cascade inputs can reuse declaration entries while their backing rules remain private. When a private rule contains 24 to 512 literal custom properties totaling at most 32,768 UTF-16 units in names and values, the cascade can carry the entire block through matching descendants. Local declarations with disjoint names remain independently accessible in the computed snapshot. A competing declaration for a projected name goes through winner resolution. The [disjoint theme study](disjoint-theme-reuse.md) measures this path in Ant Design and Material UI. The [stylesheet churn and worker residency study](stylesheet-churn-and-worker-residency.md) records the measured effects and remaining cascade costs.

## Contracts and tests

TypeScript browser-facing APIs use exception contracts where the platform requires them. Rust topology failures use typed `Result` and leave the graph unchanged. The native package uses Zod non-throwing request/snapshot/configuration schemas and derives their TypeScript types. neverthrow supplies Result, ResultAsync, ok and err; `packages/html-parser/src/invariant.ts` supplies invariant and InvariantError. Addon availability and validation errors return typed Results; standard browser facade exceptions retain their platform contracts.

Each owned source file starts with its durable responsibility. Public entry points document examples and limitations. Use Vitest `test/*.test.ts` beside the owning package and Cargo integration tests in `crates/dom-core/tests/`.

The upstream qualification target is jsdom 31.0.1 at commit `b76da26fd3b2786771b493f0bbec8dbd7a3d36d0`. Qualification requires packed Node alias tests, named upstream jsdom and WPT outcomes, and runner fixtures on both backends once integrated. Record missing assertions, harness failures, and browser-confirmed differences separately. Require equal checked behavior before comparing implementations. Run benchmarks uncached in serial fresh processes and record Node version, provider versions, platform, startup, verified completion, warm work, and memory separately.

### Upstream API probe

Prepare a separate, unchanged checkout and install its locked test dependencies.

```sh
git clone --depth 1 --branch v31.0.1 https://github.com/jsdom/jsdom.git .cache/jsdom-reference
npm --prefix .cache/jsdom-reference ci
bun run build
bun run conformance:api reference
bun run conformance:api candidate
```

Both commands invoke upstream’s API test script. The candidate process redirects resolution of the upstream public API entry point to the built CommonJS or ESM facade according to the caller’s module format. Direct imports of upstream internals still exercise the reference and must be excluded from candidate parity claims. Pass Mocha arguments after the provider to focus on specific test names. The upstream WPT submodule is pinned to `2971340498805350babb6c167e0df98eaa380f98`. WPT requires its own fixture server and outcome reporting.

### Packed Vitest alias

Run `bun run conformance:vitest` to build and pack both TypeScript packages, install them in an isolated project under the `jsdom` dependency name, and run Vitest 5.1.0 with its built-in jsdom environment in the `forks`, `threads`, `vmForks`, and `vmThreads` pools. The fixture checks DOM event dispatch, Blob and multipart request bytes, Blob URLs, and constructor identity across the host environment and test imports. The same packed consumer also runs React 19.3.1 with Testing Library React 16.3.3, DOM 10.4.2, and user-event 14.6.8: stateful clicks, controlled inputs and textareas, checkbox activation, select options, asynchronous effects and cleanup, portals, and server-markup hydration. Two additional stress contracts reorder/update 2,048 keyed rows while preserving an edited control, and verify sixty-four repeated checkbox/state/style changes. Setup explicitly installs cleanup hooks in each fixture so cached library imports do not suppress VM-pool cleanup. The isolated consumer installs a Node resolution guard that rejects dependencies or parent module paths in the producer checkout. It verifies a real stylesheet/query through both entry formats before running every pool with the guard inherited by workers. Earlier packed reports without this guard do not prove independence from the producer checkout. Both entry formats load the facade through Node's host module cache. Each `JSDOM` instance still creates its own Window and DOM constructors.

### Smoke benchmark

Run `bun run benchmark > .cache/benchmark-smoke.json` without other suites running. It verifies identical work on RunDOM, jsdom 30.1.3, and Happy DOM 21.0.4. Nine serial trials per provider and workload rotate provider order. The report includes all trials, wall time for the complete process, timed DOM work, and RSS after work. Each warm workload measures 32 windows after eight warmups. The frame workload checks child document mutation and Window relationships. The stylesheet workload checks compound matching, computed color, and inline mutation. The ID workload checks 256 distinct hits and one miss in a document with 512 IDs. The table workload reads 128 rows twice through live collections and verifies an appended row and cell. The URL workload reads a relative link 128 times in a document with 512 preceding elements. The smoke benchmark does not qualify broader workloads or matched API coverage.

HTTP requests use the facade's Undici transport. Undici is loaded on the first HTTP request so parsing a string does not initialize the network stack. The DOM workspace receives functions for script loading and XMLHttpRequest and remains independent of the HTTP implementation.

### Public facade declarations

`packages/jsdom/types/jsdom.d.ts` owns the facade type contract. The package build writes format-specific declarations and derives a standard-global binding-name union from a closed built Window. Only the published facade references browser ambient declarations; private Node implementation/test compilation resolves its self-import to source through package-local TypeScript paths. Runtime tests still import the built package. No source DOM/parser declarations cross this facade boundary.

Run `bun run conformance:types` for an independently packed, strict (`skipLibCheck: false`) consumer with NodeNext ESM/CommonJS and bundler resolution. Valid examples execute in both Node formats under the producer-resolution guard; negative compiler examples check script modes, invalid CSS properties and typed query results. This gate complements API/WPT/runtime tests and makes no runtime feature-completeness claim.

Parser interfaces preserve receiver ownership through shared weak records across Windows. XML fragment errors use the invoking Window's DOMException factory. DOMString conversion rejects Symbols, and LegacyNullToEmptyString setters special-case null alone. Core Node-interface class strings derive from existing eager public bindings; lazy bindings remain lazy. Public constructor factories preserve canonical names across bundler deconfliction. Parent/child mixin unscopables belong to their concrete interface prototypes and have null-prototype tables.

HTTP redirects retain effective origin and response taint across all hops. Explicit XHR authentication is scoped to the XHR's origin and is replayed once on a permitted Basic challenge. The HTTP adapter delegates decompression to Undici while preserving wire headers; private `bodyDecoded` response metadata survives public CORS header filtering for progress accounting. XHR's upload-complete flag and its send-time upload-listener flag are distinct: reentrant open/send can change the former without enabling callbacks registered too late. Internal request events use the event system's trusted dispatch path.

CSS declaration aliases use the provider's public legacyAliasOf metadata consistently for writes, reads, priorities, removals and source-list importance. The additional size property parser delegates to one or two native width grammar values and keeps page-descriptor keywords separate. Keyframe selectors delegate to the native keyframe-selector grammar rather than a handwritten percentage whitelist. Public CSS namespace identity is an ordinary symbol descriptor.

CSS rule kinds are allocated through a shared weak record and exposed through the inherited, branded CSSRule.type getter. Constants are immutable on the constructor and prototype. Physical border serialization reads canonical components and their importance, combining only complete compatible axes or sides; unresolved substitutions retain provider provenance. Background serialization reads the complete current component block, preserving CSS-wide agreement, layer syntax, position/size coupling and origin/clip pairs. These operations do not add layout or an animation engine.

The compatibility/native integration boundaries are recorded in `docs/compatibility-native-plan.md`. Local WPT-format regressions, upstream selected WPT assertions, legacy fixtures and expected-failure improvements have separate accounting. The selected-corpus percentage cannot substitute for the local suite. A rejected Window-local File experiment demonstrated that stock Vitest can retain the host Request while replacing File, exposing Node multipart parser brand assumptions; keep the archived evidence and solve the complete integration boundary before retrying prototype isolation. Current HTML attribute escaping follows the [HTML serialization algorithm](https://html.spec.whatwg.org/multipage/parsing.html#serialising-html-fragments), with the older legacy fixture mismatch retained in qualification.

The local regression closure checkpoint passes all 2,740 reference-passing local assertions and 1,373 owned TypeScript tests. Preserve local assertion records separately from Mocha expected-failure events: improvements can fail an unchanged expected-failure wrapper. Its transaction, namespace, declaration-order and document-lifetime contracts live in `local-regression-contracts`, `selector-namespace-contracts`, `border-declaration-state-contracts` and `document-lifetime-completion-contracts` tests. External script load completion continues through its resource promise after execution starts; queued navigation is suppressed after document destruction. FileReader load and loadend share the completion task with a reentrancy generation guard. Pending stylesheet replacement prevents concurrent mutation. Parser optimization must preserve all these contracts.

Native host artifacts build through `packages/html-parser/scripts/build.mjs` with an explicit compiler host target, release Cargo profile and locked dependencies. The package records the target, compiler and Node-API level. Turbo native build caching stays disabled until platform/compiler/libc identity has complete portable keys; Cargo incremental compilation remains active. Independently packed consumers install html-parser, dom and jsdom tarballs with explicit local overrides and the existing producer-resolution guard. Rust-selected Vitest adds a fixture requiring one actual native parse and one counted surrogate fallback in each pool. `bun run conformance:native` preserves all tree-construction source hashes and distinguishes reference-passing cases, native improvements, shared fixture failures and fragment exclusions.

The selector/snapshot allocation batch keeps shared predicate caches exclusively scope-independent; scoped predicates remain receiver-local. CSS declaration public prototypes are separate from private native-backed implementations in css-declaration-view.ts. Supported indices are readonly, private storage is hidden, and preventExtensions rejects as in the reference. Public methods validate receivers/conversions before invoking private operations; native realm iterators read public indices. Every public readonly mutation reaches its DOMException path before mutable-class private methods. Computed read contexts share immutable completed data behind fresh views, replacing per-result copy-on-write maps. Indexed reflection, rejected freezing, live updates after mutation and foreign-window borrowed operations remain covered by public contracts.

The native transport is now compact wire version two; `compact-transport.ts` checks storage/header/Unicode bounds and `snapshot-ownership.ts` owns shared graph semantics for both compact decoding and object-schema validation. The public parseHTML result remains the version-one object snapshot. `object-schema.ts` extends the public Zod core object interpreter because ordinary Zod object construction can generate functions at runtime; retain the no-eval subprocess contract and avoid changing shared Zod configuration. Native words use captured typed-array/ArrayBuffer metadata getters, not replaceable public properties. ### November 27 optimization batch

Vitest reads every Window global once per test file. Those reads must stay cheap: reading Window globals never initializes the CSS reference grammar. The pinned jsdom CSS reference is split into `css-reference-interfaces` (the IDL wrappers RunDOM names), `css-reference-properties` (property definitions and shorthands) and `css-reference` (the engine), each with code-only cache data. Requests between them go through the owning artifact's `load()`, so one reference module graph exists per process. Reading Window globals loads only the interfaces artifact, and computed styles of simple declarations load only the property tables. New `rundom-css-reference/` paths must be added to the table in `css-reference-runtime.ts`; a named path that is not bundled fails the build. CSS artifact loaders hash file bytes, not decoded source. `css-reference-loading.test.ts` pins the module-free read, and the `globals-read` lab scenario measures it; its first-use phase is the regression signal. Reading `Request` still triggers Node's own lazy setup of built-in fetch.

Unescaped ASCII selectors covering type, id, class, attribute, combinator, nth, structural, state and `:not`/`:is`/`:where` syntax are parsed directly by `selector-parser.ts` (256 cached parses of up to 4,096 code units). Their predicates, candidate hints, reuse eligibility and negation validity are produced without loading css-tree, css-select or the reference grammar. Other syntax uses the general adapter, and `selector-direct-contracts.test.ts` compares both paths on HTML and XML documents.

Computed-style views keep their source, owning resolver and connectivity in module-private native slots on the never-escaping proxy target. The public proxy carries a single slot pointing at its target, because V8 private fields on proxies cost several times more than on ordinary objects. Declaration registration stores the owning view factory and interface choice in native slots. Inline-view and deferred-declaration lookups stay in WeakMaps because a proxy slot read is slower than a WeakMap get. A computed view retained after `window.close()` reads empty but keeps its source reachable through the slot.

Ancestor frames whose non-inherited winners are literal resolve only inherited values and display eagerly; their projection captures only the parent values it reads, completes on demand, and publishes ancestor reads as deferred target views. Deferred reads of undeclared independent properties use the longhand initial value, matching materialization. Frames whose evaluator values depend only on winners and the ancestor chain are static: reusable, and not extended to descendants. Context-free winners on allowlisted properties resolve once per process, keyed by their text and any referenced custom properties declared on the frame.

Substitution frames parse each cascade winner on its first resolver lookup and keep the result for that frame. Values containing `random(` or `random-item(` are parsed eagerly in declaration order so draws do not change. The css-tree `E4.Object.assign.SyntaxError` profile frame is the parser entry point, not Error construction.

Event metadata (dispatch state, trust, timestamp, cancellation, early stop, legacy-uninitialized state, mouse brand and related target) lives in one module-level private slot added at construction. The brand still holds across borrowed Windows and adoption. When no node on the path has a listener for the type after pre-activation and there is no related target, dispatch skips propagation; activation, default actions and final target state are unchanged.

Insertion builds MutationObserver records only when observers or XPath versions exist, and inserted-subtree scans use explicit stacks. HTML replacement invalidation keeps one retained stack and allocates nothing per removed child.

DOMParser text/html, `Document.parseHTMLUnsafe`, detached `document.close()` and the jsdom `parseDocument` hook share the recurring-source cache with Window construction unless details or declarative-shadow parsing callbacks are needed. The native kernel remains Window-only. Heavy DOMParser use can therefore evict Window recipes from the eight-key cache.

Interface descriptor tables are installed after switching the target to dictionary mode (`useDictionaryProperties`); fast-mode installation copies the descriptor array for each property.

Rejected in this batch, with measurements in the pull request: moving descriptor tables into class static blocks (more instructions per Window); lazy per-Window subsystems and lazy interface families (need accessors or a Proxy Window, which changes `getOwnPropertyDescriptor` results); a cheaper replacement for per-wrapper `markAsUncloneable` (Node's mark is an own private symbol, so marking a prototype does not protect instances); a markup-regex shortcut for the named-property index of parsed documents (cost moved into `querySelectorAll`); per-dispatch listener snapshots; memoizing `CSS.supports` and stylesheet syntax (the cost was cold loading and unique parses). The same warm work costs about 20–26% more instructions per operation once it spans two or more Windows, because every Window builds its own copies of the hot helpers (separate feedback and optimized code, lost inlining) and the shared record lookup sees every Window's wrapper classes; the November 28 batch moved tree-walk and attribute bodies to module level for that reason.

### November 28 optimization batch

Measurement. Load-immune counts come from `node packages/jsdom/bench/lab/probe.ts` (see [performance laboratory](performance-lab.md)); compare instructions between builds only from alternated runs and treat differences under 3% as noise. `qualification/compare.py OLD NEW` compares two downloaded qualify.yml runs. Instruction comparisons of Vitest runs must use `--pool=threads`: with forks, `/usr/bin/time` does not count the test worker. The frameworks job runs one untimed warmup before the timed providers, because Svelte caches compiled samples on disk and the first provider otherwise pays for compilation inside its "dom" variants.

Computed style. Completed frames are reused far more precisely: `var()` frames are static when every referenced token depends only on cascade winners; inline-styled elements can reuse completed frames, because every inline change rewrites the style attribute and advances the style revision; `:hover` and `:active` never block reuse, since they never match; a focus change invalidates only frames on a focus-dependent selector path plus the element's own focus ring. A computed property write whose validation stores only its own value is remembered (4,096 keys) and replayed; border, flex, margin and padding longhands are excluded because their setters rebuild shorthands from sibling state. Media query parses are shared per text (256 entries, texts up to 1,024 characters); `matches()` reads the viewport on every call, and nothing may change a parse result in place. Closures stored in retained frames or ancestor projections must be created outside `computeStyle`: a closure keeps its creating scope alive, including the stylesheet list, and that retained every removed `<style>` element until the Window closed. An element without its own frame may adopt the frame of a sibling with the same namespace, tag, role and form-control kind under the same parent frame (last four per shape) when its freshly matched inputs, user-agent context and environment are equal. It keeps a copy carrying its own proof, and copies share a family, so descendants fit under any copy; adoption never certifies the owner's frame. The process-wide memo of context-free winners must exclude any value whose meaning depends on the element: flow-relative position keywords (`block-start`, `inline-end`, `x-start`, …) resolve through writing mode and direction and are never memoized.

Stylesheets and inline declarations. Comment-free flat stylesheets of any size (rules and simple width/height media groups) are read by `css-flat-sheet.ts` into the parser's tree with unread declaration blocks; anything that needs recovery uses css-tree, and `flat-stylesheet-contracts.test.ts` compares both paths. Stylesheet declaration blocks are parsed once per rule per process. An inline declaration reuses its last published serialization as the before text until the next mutation. Specified-value serialization and cssstyle's acceptance verdict are each kept for up to 4,096 entries per property and value; values containing `random` are not kept. Blocks without cssstyle shorthands or `border*` names are serialized directly in declaration order; re-check that on any cssstyle upgrade. The source document's base URL cache is invalidated only by base element insertion or removal, base `href` changes, the end of parsing and fallback URL changes; inline sheets still resolve the base when they attach. A block declaring every longhand of a jsdom shorthand is serialized by jsdom's block serializer in index order, without cssstyle's stored shorthand entries; outline uses jsdom's shorthand serializer. Public declaration indices (`length`, `item()`, iteration) are computed from stored entries and are longhand-only, as in jsdom; a shorthand or legacy alias that reads as empty while every longhand in jsdom's shorthand table is stored is serialized through the reference declaration, which `css/cssom/cssom-getPropertyValue-common-checks.html` depends on. Standard property names are matched ASCII case-insensitively by `getPropertyValue`, `getPropertyPriority` and `removeProperty`; custom properties stay case-sensitive. Parsed sheets, links and style attributes before the first `<base href>` keep the fallback base. Media queries made only of lowercase px width/height range features, optionally after `screen`, `only screen` or `all`, are serialized and matched without the reference engine (`css-media-direct.test.ts` compares them with the grammar); the fast path assumes the fixed 1024x768 default device.

Tree and selectors. Insertion scans record per-element subtree kind summaries (`subtree-summary.ts`) for detached insertions and skip recorded subtrees that cannot matter. Summaries may stay true after removal but are never missing a kind; every raw insertion into an existing parent must call `invalidateSubtreeSummaries`. The cycle check is constant for nodes with no children, shadow root or template content. Insertions into trees outside the source document skip ID index invalidation. Tree-walk getters and attribute get/has/set/remove run module-level bodies over the shared node records, and each per-Window getter passes its own `raw`/`element`/`wrap` for foreign or unrecorded receivers. `nodeRecord` reads the private slot directly in try/catch; keep the `in` check for receivers that may be Windows. Direct-grammar selector lists and attribute/pseudo compounds reject elements by a 30-bit lowercased name signature (tag, attribute names, id, class tokens) before running predicates; `attributeChanged` invalidates the signature. Selectors outside the direct grammar, plain type/class/id selectors and `:not()` contents are never used to reject. Never call `records.read` where a non-node can arrive (Window, AbortSignal, the end of an event path): a failed private read throws and costs about 30k instructions; use `records.get` or `nodeRecord(x, true)`. Identity members of a node (`childNodes`, `children`, `classList`, `attributes`, `style`, `dataset`) always come from its own Window, whichever Window's getter reads them. Dispatch path binding wraps each ancestor once and writes a parent link only when it changed; button activation computes the form owner before disabled state and connection; pointer-input tracking for `:focus-visible` walks to the root only when the document's pointer state would change. `EventTarget.prototype.dispatchEvent` called directly on a node propagates through its ancestors.

Window assembly. Constructors and prototypes created per Window receive constant and accessor tables only through `installInterfaceTable`; `defineProperties` on a fresh, non-dictionary object costs several times more. Do not do named property reads on the WindowMembers holder object; read its members through their descriptors. `window-assembly-contracts.test.ts` pins the full global surface in `test/__snapshots__/window-surface.{host,vm}.txt`. RunDOM resolves `node:assert/strict`, `node:fs/promises` and `node:stream/web` at first use, and the CSS runtime embeds css-tree's patched syntax data (`css-tree-data.test.ts` guards it); `startup-loading.test.ts` pins the artifacts loaded at each start-up phase. Reading `Request` still loads Node's undici, which itself loads crypto, zlib, http, tls, perf_hooks and worker_threads.

Vitest. `@run-dom/jsdom/vitest-environment` is an opt-in environment that matches the built-in jsdom environment but resolves Window-only globals on first use; host-defined keys are resolved at setup because Window getters read host classes from `globalThis`. See [Vitest preset](vitest-preset.md).

jsdom parity fixes found on the way: `box-shadow: none` computes to `none`, and `blur()` does not re-check focusability. Percent opacity values are stored as numbers, and dataset and token-list error messages match jsdom's. One difference is deliberate: an error thrown by a listener is reported to the listener's own realm, as the specification requires; jsdom reports it to the target's Window.

Rejected in this batch, with measurements in the pull request: table-generated interface members (class bodies are the cheapest way to create the per-Window functions identity requires: 1.2k instructions per method against 3.6–4.5k with a table loop or `bind`); a packed, disk-persisted stylesheet, selector or HTML parse cache and sharing it across threads (parsing distinct inputs is 0.8–1.4% of Material UI worker CPU; inputs repeat across runs but rarely across test files); Node startup snapshots (built-in modules only, and `SharedArrayBuffer`/`Float16Array` are absent while building); per-rule prepared declarations (blocks were already parsed once per process); warming the CSS caches by running real CSS paths at build time; recording subtree summaries on connected insertions (about 6% parse cost); a display-only focus check (the frame `focus()` builds is reused by the next read); dictionary-mode installation of the Event, WheelEvent and KeyboardEvent constant tables; moving `textContent` and `matches`/`closest` entry points to shared code; caching longhand lookups for shorthands and a cache filled by the `cssText` getter (unsafe); lazy inline-sheet base capture (base resolution is observable at attachment); a module-level dispatch core (no instruction change at 1–8 Windows; the multi-Window cost was in activation and path binding); a cheaper wrapper-to-record read (a field in a shared base class saves about 20 instructions per read at 12 classes, a WeakMap is flat at about 140 and slower); shrinking or dropping the CSS runtime code cache (start-up cost is execution, not deserialization); sha256 to crc32 for the artifact cache check; sharing cssstyle's forked lexer.
