# Optimization exploration ledger

Goal: explore and verify the material optimization paths, integrating useful changes while preserving drop-in behavior. Coverage means a falsifiable hypothesis, representative cross-scenario measurements, correctness/lifetime checks and a retained or rejected decision. It does not mean every possible algorithm has been enumerated. This ledger tracks remaining work; [optimization opportunities](optimization-opportunities.md) owns detailed findings, and [qualification](qualification.md) owns compatibility claims.

No timing/profiling overlaps a build or correctness run. Cohorts are immutable and independent, provider behavior must pass the same work checks, and all current host measurements are exploratory. Long lists alone cannot select a default: construction/first use, reads, queries, mutations, events/interactions, styles/roles, parsing/serialization, worker throughput and live/closed/released memory remain separate axes.
