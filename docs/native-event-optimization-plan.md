# Native reuse and event metadata selection

Target two measured costs independently: repeated native tokenization/validation, and base Event construction/dispatch metadata hashing. Existing document parsing keeps a one-entry TypeScript raw template only after repetition. Prototype the equivalent admission for an opaque native arena: at most 1,048,576 markup code units and 32,768 arena slots, key includes exact markup and scripting flag, unique parses retain no arena, and each reuse allocates independent canonical raw records. Keep native public parse operations uncached; actual invocation counts must reveal reuse rather than presenting a cache hit as fresh Rust work. Fallbacks remain checked before cache admission. Verify repeated documents after mutation/adoption/closure, alternating inputs, large rejected admission and actual-call accounting.

The qualified fragment checkpoint's default-action CPU samples identify Event construction (~134 ms self), dispatch (~82 ms), GC (~48 ms), and trust marking (~33 ms) over nine profiled batches. Test one shared weak Event metadata record for timestamp, dispatch state and trust phase, removing three separate weak maps. Public function/class/descriptor identity remains unchanged. No event object pooling or path reuse across author callbacks is allowed.

Run focused correctness before freezing variants. Compare arena-only base, bounded-native-reuse-only, event-metadata-only and combined where attribution matters.
