## Batch 2: query and computed-style costs

The qualified 441-trial performance refresh separates process startup, DOM work, first use and warm execution. RunDOM beats jsdom on the checked workloads and beats Happy DOM on checked construction. Happy DOM is about three times faster on warm role queries, and eligible TurboDOM operations remain faster. The first RunDOM role query costs about 55 ms.

CPU profiles identify selector-cache lookup preparation, repeated computed-style cascade/winner comparison and computed declaration copying. Address these as one allocation/invalidation batch. Scope-independent selector hits should reuse their compiled predicates without repeating scope classification. Completed computed declarations should produce independent readonly public views without rebuilding mutable declaration state. Reuse depends on actual private mutation, stylesheet, scope, viewport, base-URL and inheritance dependencies; public getter overrides must not change those authorities.

The contract examples include alternating :scope receivers, escaped names, HTML/XML/foreign namespaces, attribute and stylesheet mutation between reads, inherited color and custom properties, media changes, retained computed views, readonly mutation exceptions, enumeration and borrowed methods across Windows. Run the complete CSS and local regression selections before an immutable full run. Re-run the same fresh-process benchmarks serially after correctness qualification, including checked large and small role-query fixtures and framework workflows. A faster microbenchmark alone does not qualify a default change.

## Batch 3: a Rust parsing kernel with a measurable boundary

Keep browser objects, callbacks, events and lifecycle algorithms in TypeScript. Add a project-owned Node-API package backed by the canonical Rust workspace. Use html5ever's HTML tokenizer/tree-builder through a Rust arena sink; carry node kinds, namespace-aware attributes, document mode, template contents and parser form associations through a versioned bulk snapshot. The TypeScript decoder validates counts, indices, kinds and string spans, then materializes the existing private tree records in one boundary crossing. Avoid one native call per node or property.

Start with inactive document parsing, including malformed markup, foster parenting, foreign content, templates and form ownership. Source locations and active incremental script parsing retain their complete existing paths until the kernel supports their contracts. Explicit native selection must report addon/ABI failure; capability fallback must be recorded in qualification so a mostly-TypeScript run cannot be presented as Rust coverage. Input conversion must preserve the existing UTF-16 contract, including an explicit complete fallback for unsupported surrogate inputs.

Node-API bindings and generated TypeScript declarations belong to a separate package; the public jsdom facade keeps its existing standard API. Packaging must load the correct platform binary independently of the producer checkout. Turborepo cache keys must include the native target, compiler/toolchain inputs and ABI, and retain Cargo incremental caching. Validate native payloads and errors at the boundary. No native library, raw node identity or mutable shared document crosses into public browser objects.

Qualify the same parsing examples in both tracks, the HTML tree-construction corpus, packed ESM/CommonJS consumers and the framework fixtures. Record how many parser operations actually use Rust. Measure native initialization, parsing, transfer and TypeScript materialization separately, then end-to-end fixture construction, startup and RSS. Choose the default only from verified compatibility and repeated end-to-end measurements.

## Binary ownership investigation

The archived binary experiment repairs thirteen reference-passing assertions locally but breaks stock Vitest's multipart flow when Vitest replaces File while retaining Node's Request. Native multipart parsing combines a captured File brand assertion with the current global File constructor. A real Window-local File prototype exposes that mismatch. A Window Request parser adapter does not repair callers that retain the host Request.

The experiment, dependency changes and new source modules were removed from the active build. Its source and failing consumer/contract reports remain under `.cache/qualification/binary-realm-experiment-*`. The experiment was rolled back before the subsequent local regression closure batch. Future work must solve the complete binary/global integration boundary and retain real prototype inheritance and native multipart behavior; global Object/Reflect substitutions and fake instanceof results do not establish compatibility.

Sources: [Node-API package setup](https://napi.rs/docs/introduction/getting-started), [html5ever parser interfaces](https://docs.rs/html5ever/latest/html5ever/), [HTML serialization](https://html.spec.whatwg.org/multipage/parsing.html#serialising-html-fragments).

## Next substantial optimization batch

The completed local closure full run reaches 99.85697% of reference-passing selected assertions, with 266 failing and thirteen missing. It repairs thirteen reference-passing assertions but loses three previous FileReader improvements shared with the reference; retain that callback-checkpoint gap in acceptance reports. The new allocation changes cut warm role-query medians by 5–6%, while first use still costs about 54 ms and Happy DOM remains about three times faster on warmed roles.

The native JSON boundary is now measured: its snapshot is approximately ten times the input size, and JSON decoding plus schema cloning/graph validation costs more than native parsing, serialization and transfer together. The next kernel batch should replace the repeated JSON records with a versioned compact transport and a shared immutable string pool, validate all counts/spans/ownership edges before private DOM allocation, preserve both module formats and VM host-cache identity, and requalify all 3,464 parser trials, unsupported-input fallbacks and packed native consumers. Include corrupt/truncated/overflowing headers, unknown versions and kinds, duplicate parents, cycles, namespace errors, template/form references and astral string-span boundaries as explicit contracts. Keep the complete existing fallback paths and expose native coverage. Measure boundary stages and end-to-end parsing before selecting a default.

Treat persistent Rust-backed browser storage as a separate future architecture boundary. A faster parser alone cannot remove TypeScript tree materialization or fix CSS hot paths. The computed-style batch still needs private dependency authority for mutation/control/focus/stylesheet/adoption/viewport/base-URL state before skipping repeated cascade construction. Public getter overrides and retained snapshots remain acceptance cases.

The compact transport batch is implemented and qualified: fixed integer sections, shared Unicode storage, no runtime validator code generation, captured storage metadata and one semantic ownership authority. Thirty-two boundary contracts and seven Rust tests pass. The 3,464 real native parser trials retain their outcomes, and strict packed consumers plus four Vitest pools pass. The next main performance batch targets repeated CSS cascade work and its private dependency authorities, with the stated mutation/control/focus/stylesheet/adoption/viewport/base-URL contracts.
