# Validated native arena handoff

The Rust backend already parses and emits compact version-two wire storage in one addon call. The current JavaScript boundary validates and materializes a complete version-one object snapshot, then DOM code allocates a second canonical raw tree. Native leaf profiling also identifies tokenizer/tendril work and string-pool hashing; compiler-only LTO experiments did not establish a useful complete-DOM gain. Default TypeScript remains faster in the current complete parsing scenarios.

Prototype an opaque validated arena returned only from a fresh owned native parse. Keep raw mutable words private; callers must not obtain an alias that can invalidate checked ownership. Complete storage, namespace, Unicode-span, node-kind, template/form, unique-parent and cycle validation before any DOM materialization. Share semantic ownership checks with the existing object snapshot schema rather than maintaining two definitions of valid trees. Preserve the stable parseHTML snapshot API and all typed request/addon/snapshot failures; a new internal cross-workspace arena contract can avoid intermediate node/child/attribute arrays in the DOM path. Native invocation and capability fallback counts must remain visible. Rust selection stays explicit, and active/incremental, XML, fragment, source-location, custom-adapter and form fallback behavior stays unchanged.

Keep the initial candidate free of speculative span caches or new wire compression. Measure small/large unique parsing, repeated/rotating inputs, first touch and complete traversal, subsequent mutations/adoption/cloning, cold module/setup/first use, memory and actual native calls. Run decode/native/materialization CPU and allocation observations separately from timing. Only then test bounded span reuse, string-pool/tokenization changes or transport packing where the measured share supports them. Do not claim native speed from raw-addon throughput alone.

Examples cover exact public snapshots, detached parser allocations, doctype/quirks, template and foreign content, UTF-16 scalar boundaries, invalid buffers/headers/sections/edges, duplicate ownership, cycles and form references. Existing malformed-input tests must exercise the same validator used by the DOM arena. Add lifetime checks for released arena storage and retained DOM handles. Retaining the candidate requires fresh default/native tests, API/types/four-pool consumers, selected native coverage replay, complete selected DOM assertions and representative React workflows. Preserve rejected variants and their source/evidence hashes.
